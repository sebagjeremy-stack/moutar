# Moutar — vérifier la cacherout d'un produit (projet d'un médecin, usage familial d'abord)

## Règles non négociables
- **Moutar ne décide pas, il cite.** Chaque verdict porte sa SOURCE, sa DATE et sa VALIDITÉ ; jamais un « oui » ou un « non » unique sans source ; une source périmée s'affiche en ambre, jamais en « oui ». Le niveau 4 (composition) porte toujours son avertissement (équipement, arômes, lait non surveillé, vin, bichoul). L'utilisateur choisit son seuil (défaut : niveau 2).
- **Aucune donnée de santé, aucune identité** : pas de compte pour chercher, un compte simple pour contribuer ; l'historique des scans reste sur le téléphone ; aucun hébergement HDS nécessaire. Jamais une photo d'utilisateur conservée sans qu'il l'ait demandé (contribution).
- **Sources et droits** : Open Food Facts (ODbL, attribution affichée) ; listes Consistoire et Rav Wolff importées pour un usage privé, source et date sur chaque ligne ; Les Bons Plans Cachères = contributions manuelles sourcées, jamais de scraping de Facebook ; table d'additifs À NOUS, sourcée ligne par ligne (jamais recopier un site sans licence).
- **Catalogues EN CODE et testés** (certificateurs et leurs logos, additifs, rubriques des listes) ; les règles métier dans des modules PURS (`*-regles.ts` + `*.spec.ts` à côté) ; le service lit, écrit, appelle la règle.
- **L'IA propose, l'utilisateur valide d'un clic** : la reconnaissance d'un logo ou l'OCR d'une liste d'ingrédients est une PROPOSITION (organisme reconnu, texte lu) ; c'est le CODE qui calcule le verdict à partir des catalogues. Tout appel passe par un module `ia` unique (moteur compatible OpenAI : OVHcloud AI Endpoints ; journal sans contenu ; hôte hors liste = l'API ne démarre pas). Aucune identité ne part au moteur.
- **UI** : mobile d'abord, une action par écran, pouce droit ; jetons de design uniquement (jamais une couleur en dur) ; **rouge réservé à « non cacher » ou au danger**, ambre à « non vérifié / périmé / en attente », vert à « permis selon la source » ; jamais une information par la seule couleur (le mot s'écrit à côté) ; contraste AA ; `prefers-reduced-motion` ; 16 px pour le corps ; 14 px tolérés pour les métadonnées et pastilles (décision du 20/10/2026). Tout en français.
- **Direction visuelle (20/10/2026, décision du médecin-utilisateur) : FUN et COLORÉE**, pas la sobriété clinique de Kora. Une identité joyeuse (palette vive à plusieurs teintes d'accent, formes rondes, illustrations ou emoji sobres, micro-animations courtes et coupées par `prefers-reduced-motion`, ton chaleureux dans les textes), SANS toucher aux garde-fous ci-dessus : les couleurs sémantiques (vert, ambre, rouge, neutre) gardent leur sens exclusif et ne servent jamais de décoration ; les teintes d'accent servent au reste (marque, boutons, fonds, illustrations).
- Secrets en variables d'env ; un jeton ne se garde que HACHÉ ; soft-delete uniquement. **Deux chaînes de base** : `DATABASE_URL` = l'API, rôle `moutar_app` (journaux en ajout seul par les DROITS, `database/droits-application.ts`) ; `DATABASE_URL_MIGRATIONS` = le propriétaire, pour migrations, graines et `db:droits` seulement ; en production, l'API refuse de démarrer avec le propriétaire.
- **Console d'administration** (`/admin`, décidée le 20/10/2026) : login + mot de passe (hash argon2id ou bcrypt, 10 essais / 15 min par e-mail et par IP, réponse identique que le compte existe ou non), cookie de session HttpOnly dont le jeton est HACHÉ en base, session relue en base à chaque requête, garde sur TOUT `/api/v1/admin/*` ; chaque écriture s'inscrit dans `journal_admin` (ajout seul). La console règle les catalogues (surcharges d'additifs et de certificateurs), importe les listes, valide les contributions ; elle ne voit aucune donnée personnelle (il n'y en a pas).
- **Moteur d'IA : deux fournisseurs interchangeables derrière UN module `ia`** (décision du 20/10/2026) : OVHcloud AI Endpoints par défaut (compatible OpenAI, UE : vision `Qwen2.5-VL-72B-Instruct`, audio `whisper-large-v3-turbo`, texte `gpt-oss-120b`) ; **Claude par le SDK officiel `@anthropic-ai/sdk`** dès que `ANTHROPIC_API_KEY` est posée (`IA_FOURNISSEUR=anthropic`, modèle par défaut `claude-opus-5-5`), attendu meilleur sur la lecture des étiquettes et des logos ; choix final au lot 3 sur de vraies photos. Jamais une clé dans le code ni dans un fichier suivi par git ; le code ne lit que le NOM de la variable.

## Stack (celle de Kora, reprise)
Monorepo pnpm : `apps/web` (React 18 + Vite + Tailwind, PWA, port 5273, proxy `/api` → 3100), `apps/api` (NestJS + Drizzle + PostgreSQL, validation zod, port 3100), `packages/shared-types` (types et règles pures partagées, lu par `tsx`). Postgres de dev : `scripts/dev-db.sh` (port 5433, `.devstack/pg/pgdata`). Code-barres lu dans le navigateur ; dictée par la Web Speech API ; vision et OCR par OVHcloud AI Endpoints.
Maquettes HTML statiques dans `mockups/` AVANT tout écran (jetons dans `mockups/moutar.css`).
