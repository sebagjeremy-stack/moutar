## Décisions
- **Schéma** (migration `0002_listes`) : `liste_officielle` (code `consistoire_paris` | `rav_wolff`, titre, `publie_le` et `valable_jusqu_au` en **colonnes `date`** — des JOURS `AAAA-MM-JJ`, aucun fuseau n'entre en jeu —, `importe_le`, `fichier_nom`, `note_source` (l'introduction de la source), `active`, `deleted_at`) ; **une seule liste active par code** (index unique partiel `liste_officielle_active_par_code_idx`). `ligne_liste` (rubrique, marque, produit_libelle, mention, `toute_marque`, `rubrique_reservee`, `ordre`, colonnes normalisées `rubrique_norm`, `marque_norm`, `produit_norm`, `deleted_at`). `produit` reçoit `nom_norm` et `marque_norm` (tenues à chaque écriture, `produits.service.ts : normes`). Index : `(liste_id, marque_norm)`, `(liste_id, ordre)`, trigram GIN (`pg_trgm`, extension de confiance : créée par la migration sans superutilisateur) sur les cinq colonnes normalisées.
- **Normalisation APPLICATIVE, une seule règle** (`packages/shared-types/src/regles/normalisation.ts`, testée) : minuscules, accents retirés (NFD), « œ » → « oe », tout ce qui n'est ni lettre ni chiffre devient une espace. `unaccent` n'est pas utilisé (deux normalisations auraient divergé). La migration remplit les colonnes des produits déjà lus par une approximation SQL (accents courants) ; toute écriture suivante passe par le code.
- **Catalogue en code** `catalogues/rubriques-listes.ts` : rubriques RÉSERVÉES (viande, charcuterie, vin, jus de raisin, fromage — cadrage § 2 — plus « volaille » et « boucherie » par prudence, **à valider**), mots vides d'une rubrique, mentions connues (`lait_non_surveille` → « lait non surveillé »).
- **Analyseurs PURS** (`modules/listes/analyse-liste-commun.ts`, `-consistoire.ts`, `-rav-wolff.ts`, `-csv.ts`, 25 tests sur des échantillons **FICTIFS**). Heuristiques :
  - une ligne en MAJUSCULES (trois lettres au moins, aucune minuscule) ou terminée par « : » (**quatre mots au plus**, sinon avertissement « ligne ignorée ») est une rubrique ; pour le Rav Wolff, un titre court (≤ 4 mots, capitale initiale, sans chiffre ni ponctuation) isolé par une ligne vide l'est aussi — **jamais la première ligne du fichier** (le préambule n'est jamais perdu) ;
  - **une ligne en MAJUSCULES d'un ou deux mots, collée (sans ligne vide) à la rubrique courante ou à ses marques, et sans aucune ligne sous elle, est une MARQUE de cette rubrique** (« CANDIA » entre « YAOURTS » et « BISCUITS », « LU » entre « BISCUITS » et « CONFITURES » : l'ancien piège), signalée par un avertissement nommé ; jamais pour une rubrique réservée (« VINS », vide par nature) ;
  - sous une rubrique : « Lu » (marque), « Lu : Petit Beurre, Prince » ou « Lu – Petit Beurre » (une marque, une ligne par produit nommé), « Lu, Bonne Maman » (plusieurs marques) ; **une marque contient au moins une lettre** (« 15 », « 2024 » : ignorées, avertissement) ; une marque d'un seul caractère est gardée mais signalée ; une ligne finissant par « - » au milieu d'un mot se recolle à la suivante (« Bonne Ma- / man ») ;
  - « (L) », « (l) », « lait non surveillé » → mention `lait_non_surveille`, retirée du nom ; une autre parenthèse finale → mention libre ; une mention sur la rubrique elle-même (« PÂTES À TARTINER (L) ») vaut pour toutes ses lignes ;
  - la ligne « Toutes marques » (testée AVANT la rubrique : « TOUTES MARQUES » n'en est pas une) → une ligne `touteMarque` ; une rubrique sans aucune ligne aussi, mais avec un **avertissement qui la nomme** (« Rubrique « CANDIA » sans aucune marque : lue comme “toute marque autorisée” — est-ce une marque ? ») ; une rubrique RÉSERVÉE n'est jamais « toute marque » (avertissement, aucune ligne) ;
  - « sauf », « excepté », « hors », « voir », « cf. » n'importe où dans une ligne → avertissement qui cite la ligne (restriction ou renvoi non suivi) ; un renvoi en tête de ligne ou en produit (« Milka : voir CONFISERIE ») n'est pas lu comme une marque ni un produit ;
  - ce qui précède la première rubrique est la `note` (introduction) ; bruit ignoré sans avertissement : numéros de page (« 3 », « page 3 », « - 3 - »), filets, lignes d'un caractère, code-barres nu, « Produits 2025-2026 », « Consistoire de Paris », « Rav Wolff », et toute ligne égale au **titre fourni** à l'aperçu (`titre`, facultatif) ;
  - CSV `rubrique;marque;produit;mention` (séparateur deviné : « ; », « , » ou tabulation ; en-tête facultatif ; guillemets tolérés).
  - Chaque analyseur rend `{ lignes, avertissements, note }` ; **la console corrige les lignes à l'aperçu** avant l'import. À régler sur les vrais fichiers (une ligne en majuscules en FIN de fichier, sans rien dessous, est lue comme une marque — le choix le plus protecteur, signalé —, **à valider**).
- **PDF** : `pdf-parse` 1.1.1 côté serveur (sans réseau), chargé par `pdf-parse/lib/pdf-parse.js` (son `index.js` entre en « mode débogage » et lit un fichier de test quand il est chargé sans `module.parent`, ce qui est le cas sous `import()` — déclaration de type dans `pdf-parse-lib.d.ts`). C'est le CONTENU (`%PDF`) qui dit qu'un fichier est un PDF, jamais l'extension. Un PDF sans texte (scan) ou illisible → 422 `pdf_illisible` ; le motif va au journal du serveur, jamais au client. Un fichier non PDF est lu en UTF-8 (latin-1 si l'UTF-8 ne tient pas).
- **Import** (`ListesService.importer`) : dans UNE transaction, **sous le verrou `pg_advisory_xact_lock(hashtext('liste:<code>'))`** (pris aussi à l'activation), l'ancienne liste active du même code passe `active = false` (elle reste lisible et modifiable), la liste et ses lignes (lots de 500) s'écrivent, le journal note `liste.import` (code, titre, nombre de lignes, fichier, dates). Aucune ligne → 400 `liste_vide` ; ligne incohérente → 400 `ligne_invalide` (laquelle), rien n'est écrit ; une violation de l'index « une seule active par code » (`23505`, attrapée dans le service) → 409 `import_concurrent`. **`rubriqueReservee` est RECALCULÉ** (drapeau reçu OU `rubriqueReservee(rubrique)`) à l'import, à l'ajout et à la modification, AVANT `verifierLigne` : `{ rubrique: 'VINS', touteMarque: true, rubriqueReservee: false }` → 400 ; renommer une ligne en « VINS » la rend réservée quoi qu'on envoie ; renommer vers une rubrique ordinaire oublie le drapeau d'avant (sauf s'il est renvoyé coché). `verifierLigne` (pure) : « toute marque » exclut marque et produit et jamais sous une rubrique réservée ; une ligne nomme une marque ou un produit, ou vaut « toute marque ». Une mention saisie « L » / « (L) » / « lait non surveillé » devient `lait_non_surveille` (`codeMention`). Le nom du fichier reçu est borné à 300 caractères, sans caractère de contrôle (`nomFichierSur`).
- **Journal** : `liste.import`, `liste.modification`, `ligne.ajout`, `ligne.modification` (avant / après), `ligne.suppression` ; une seule voie, `journaliserSur(db | tx, …)` (`admin.service.ts`), dans la transaction quand il y en a une.
- **Correspondance** (`modules/listes/correspondance-liste-regles.ts`, pure, 15 tests) : pour un produit (nom, marque) et une liste active, `cite` quand une ligne nomme la marque en MOTS ENTIERS normalisés (« Lu » jamais dans « Lutine » ; la marque se cherche dans « marque + nom ») — et, si la ligne nomme aussi un produit, que ce libellé figure dans le nom — ou quand une ligne sans marque nomme un produit (libellé ≥ 4 caractères) qui figure dans le nom ; `cite_par_rubrique` quand aucune marque ne correspond mais qu'une rubrique « toute marque » partage un radical (pluriel toléré, mots vides exclus) avec l'un des **DEUX premiers mots** du nom, hors mots génériques (`MOTS_GENERIQUES` : lait, chocolat, fruit(s), sucre, pâte(s), sauce, crème, nature, bio — « LAIT » ne cite pas « Chocolat au lait », « YAOURTS » cite « Yaourt nature ») ; une marque de liste sans lettre (« 15 - ») ne cite rien ; `non_cite` sinon ; `perime` quand la validité de la liste est passée au jour du centre. **Confiance** : `forte` quand la rubrique de la ligne se retrouve dans le nom du produit, `faible` sinon (marque citée pour une autre famille, peut-être) ; « par rubrique » est toujours faible. Un candidat « marque + produit » passe devant « marque seule », devant « produit seul », devant « rubrique ».
- **Carte** (`carte-regles.ts : ligneListeOfficielle`, `lignesSyntheseNiveau2`, `mentionSousLigne`) : UNE ligne de niveau 2 pour l'écran, qui porte `sousLignes` (une par liste active). Pastille : `cite` en confiance FORTE → vert « Cité · Consistoire » / « Cité · Rav Wolff » ; `cite_par_rubrique` → vert « Cité par rubrique · … », mention « rubrique « YAOURTS », toute marque » ; **`cite` en confiance FAIBLE (marque citée sous une rubrique étrangère au nom du produit) → ambre « Cité dans une autre rubrique · à vérifier », statut `non_verifie` pour la synthèse, qui dit « Non vérifié · à vérifier » (correction du 20/10/2026 demandée par le pilote, choix 2, codée au lot 3 — avant : vert « Cité » avec la mention « à vérifier », et un « Permis » en synthèse)** ; `perime` → ambre « Cité · liste périmée » ; `non_cite` → neutre « Non cité » (ce n'est PAS un « non », jamais rouge) ; aucune liste active → ambre « Non vérifié », « aucune liste importée ». La synthèse reçoit UNE `LigneSynthese` par liste (statut `cite` / `perime` / `non_cite`, validité en jour), la confiance forte d'abord ; une liste périmée seule → « Non vérifié · liste périmée » (règle du lot 1).
- **Verdicts** de niveau 2 (`enregistrerVerdictsNiveau2`) : un par liste active, écrit seulement quand l'empreinte change (liste, statut, ligne, mention, validité, confiance) ; le statut écrit est celui de la LISTE (`cite` / `non_cite`), « périmé » se lit par `valable_jusqu_au` (midi UTC du jour), jamais figé.
- **Cache** : les listes actives et leurs lignes sont gardées 30 s en mémoire (`listesActives`), oubliées à chaque écriture de la console.
- **Recherche publique** `GET /recherche?q=` : ≥ 3 caractères utiles (sinon 400 `recherche_trop_courte`), chaque mot normalisé doit figurer (`LIKE '%mot%'` sur les colonnes normalisées, index trigram), 20 produits + 20 lignes des listes ACTIVES (rubriques « toute marque » comprises, `perimee` calculée au jour du centre), **120 recherches par minute et par adresse** (429 `trop_de_demandes`) — aucune donnée personnelle.
- **Corps JSON jusqu'à 1 Mo** (`main.ts`, `bodyParser: false` + `useBodyParser`) au lieu de 100 Ko : l'import des lignes corrigées d'une liste de quelques milliers de lignes pèse plusieurs centaines de Ko ; au-delà, 413 `corps_trop_grand` (vérifié). Fichier de liste : 10 Mo (413 `fichier_trop_grand`, vérifié à 11 Mo).

## Contrat pour le web
Toutes les routes sous `/api/v1`. Erreurs : `{ code, message }` (400 `requete_invalide` avec `details` — zod, « un seul fichier », champ multipart autre que `fichier`, `lignes` en JSON illisible —, 401 `non_connecte`, 403 `session_invalide`, 404 `liste_inconnue` / `ligne_inconnue`, 409 `import_concurrent`, 413, 422 `pdf_illisible`, 429).

### `GET /produits/:ean/carte?seuil=` — niveau 2
`lignes[1]` (niveau 2) est une `LigneCarte` à laquelle s'ajoute `sousLignes: SousLigneListe[]` (vide quand aucune liste n'est active) ; `publieLe` et `valableJusquAu` y sont des JOURS `AAAA-MM-JJ` (ou null), pas des instants. Exemple : « Petit Beurre » de Lu, le Consistoire nommant la marque « Lu » sous « BISCUITS SECS » (rubrique absente du nom du produit → confiance FAIBLE, ne fonde rien) et le Rav Wolff nommant « Lu – Petit Beurre » sous « Biscuits » (confiance forte) : la ligne de niveau suit la citation forte.
```json
{ "niveau": 2, "statut": "cite", "pastille": "Cité · Rav Wolff", "ton": "ok",
  "source": "Liste du Rav Wolff 2026", "mention": null,
  "detail": "Consistoire de Paris — Produits 2025-2026 (01/07/2025), valable jusqu'au 31/07/2026 : la marque « Lu » est nommée sous la rubrique « BISCUITS SECS » — vérifiez que ce produit en relève. Mention : lait non surveillé. Liste du Rav Wolff 2026 (01/01/2026), valable jusqu'au 01/11/2026 : « Lu — Petit Beurre » nommé sous la rubrique « Biscuits ».",
  "publieLe": "2026-01-01", "valableJusquAu": "2026-11-01", "composition": null, "avertissement": null,
  "sousLignes": [
    { "listeId": "uuid", "code": "consistoire_paris", "source": "Consistoire de Paris — Produits 2025-2026",
      "publieLe": "2025-07-01", "valableJusquAu": "2026-07-31", "statut": "cite", "confiance": "faible",
      "mention": "lait non surveillé", "detail": "… : la marque « Lu » est nommée sous la rubrique « BISCUITS SECS » — vérifiez que ce produit en relève. Mention : lait non surveillé.",
      "ligne": { "id": "uuid", "rubrique": "BISCUITS SECS", "marque": "Lu", "produitLibelle": null } },
    { "listeId": "uuid", "code": "rav_wolff", "source": "Liste du Rav Wolff 2026", "publieLe": "2026-01-01", "valableJusquAu": "2026-11-01",
      "statut": "cite", "confiance": "forte", "mention": null, "detail": "… : « Lu — Petit Beurre » nommé sous la rubrique « Biscuits ».",
      "ligne": { "id": "uuid", "rubrique": "Biscuits", "marque": "Lu", "produitLibelle": "Petit Beurre" } }
  ] }
```
`statut` d'une sous-ligne : `cite` | `cite_par_rubrique` | `non_cite` | `perime` ; `confiance` : `forte` | `faible` | null. Si seul le Consistoire citait (faible), la ligne de niveau serait `statut: 'non_verifie'`, pastille ambre « Cité dans une autre rubrique · à vérifier » (lot 3, choix 2) ; la sous-ligne reste `cite` + `faible`, et l'écran lit les deux formes pareil. Pastilles possibles de la ligne : « Cité · Consistoire », « Cité · Rav Wolff », « Cité par rubrique · … », « Cité dans une autre rubrique · à vérifier » (ambre), « Cité · liste périmée », « Non cité », « Non vérifié ». La synthèse (`synthese.pastille`) dit « Permis · <mention> » ou « Permis · niveau 2 » quand une liste valide cite le produit en confiance forte.

### Console (cookie de session, `AdminGuard`)
- `GET /admin/listes` → `{ compte, listes: ListeOfficielle[] }` (actives d'abord par code, puis par date d'import ; `nombreLignes` = lignes vivantes).
- `POST /admin/listes/apercu` → **200** `{ lignes: LigneAnalysee[], avertissements: string[], note: string | null, fichierNom: string | null }`, **sans écrire**. Multipart : champs `code`, `format` (`auto` | `texte` | `csv`, défaut `auto` : `.csv` → CSV), `titre` (facultatif : les lignes du fichier égales au titre sont du bruit), fichier `fichier` (PDF, texte ou CSV, 10 Mo ; UN seul, sinon 400 `requete_invalide` « Un seul fichier à la fois ») ; ou JSON `{ code, texte, titre? }`. `fichierNom` rendu borné à 300 caractères.
- `POST /admin/listes` → `ListeOfficielle` (201). JSON `{ code, titre, publieLe?, valableJusquAu?, fichierNom?, noteSource?, lignes: LigneAnalysee[] }` (les lignes corrigées à l'aperçu ; `ordre` est recalculé dans l'ordre reçu ; `rubriqueReservee` recalculé par le serveur : reçu OU rubrique réservée) ; ou multipart avec `fichier` / `texte` SANS `lignes` (analysé puis importé tel quel ; `lignes` peut aussi être un champ multipart JSON — illisible : 400 `requete_invalide`, `details: ["lignes: JSON illisible (…)"]`). Désactive l'ancienne liste du même code, sous le verrou de la liste ; 409 `import_concurrent` si l'index unique parle quand même.
- `GET /admin/listes/:id` → `ListeOfficielle`. `PUT /admin/listes/:id` `{ titre?, publieLe?, valableJusquAu?, noteSource?, active? }` → `ListeOfficielle` (`active: true` désactive l'autre liste du même code, sous le verrou ; 409 `import_concurrent` possible).
- `GET /admin/listes/:id/lignes?q=` → `{ liste, compte, lignes: LigneListe[], tronque: boolean }` (ordre croissant ; `q` filtre sur rubrique, marque, produit normalisés, 200 caractères au plus ; 5 000 lignes au plus servies ; **`compte` est le compte RÉEL en base**, filtre compris, et `tronque: true` quand tout n'est pas servi — l'écran écrit « 5 000 lignes affichées sur N »).
- `POST /admin/listes/:id/lignes` `{ rubrique, marque?, produitLibelle?, mention?, touteMarque?, rubriqueReservee? }` → `LigneListe` (ajoutée à la fin ; `rubriqueReservee` recalculé).
- `PUT /admin/listes/:id/lignes/:ligneId` (mêmes champs, tous facultatifs, plus `ordre?`) → `LigneListe` ; `rubriqueReservee` = drapeau reçu (sinon celui d'avant, oublié si la rubrique change) OU ce que la rubrique impose. `DELETE …/lignes/:ligneId` → `{ ok: true }` (retrait doux).
- Un `publieLe` / `valableJusquAu` vide vaut null ; format `AAAA-MM-JJ`. Les champs d'un multipart arrivent en chaînes : `touteMarque` accepte `"true"` / `"false"`.
