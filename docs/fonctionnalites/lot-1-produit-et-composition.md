# Lot 1 — Code-barres → Open Food Facts → analyse de la composition (niveau 4)

Squelette du monorepo et premier lot, 20/10/2026. Rien n'est commité par la session : le pilote relit et commite.

## Décisions
- **Monorepo pnpm** : `apps/api` (NestJS 10 + Drizzle + pg + zod, `tsx` pour lire le TypeScript du paquet partagé : `--require tsx/cjs` dans `nest-cli.json`), `apps/web` (React 18 + Vite + Tailwind 3.4 + react-router, PWA par `vite-plugin-pwa`), `packages/shared-types` (types du contrat, règles pures `src/regles/`, catalogues `src/catalogues/`, résolu via `src/` sans build). Tests : **vitest** partout (l'API aussi, comme Kora : les gardes se testent avec un service simulé, sans injection Nest).
- **Ports** : web 5273 (proxy `/api` → API 3100), Postgres local 5433 (`scripts/dev-db.sh`, cluster dans `.devstack/pg/pgdata`, utilisateur et base `moutar` ; en conteneur root, le script se relance sous `postgres`).
- **Schéma** (migration `0000_initial`) : `produit`, `verdict`, `additif_surcharge`, `compte_admin`, `session_admin`, `journal_admin` (ajout seul : un déclencheur SQL refuse UPDATE et DELETE), et les tables réservées `certificateur_surcharge`, `liste_officielle`, `ligne_liste`, `contribution`. Soft-delete (`deleted_at`) sur les tables métier.
- **Catalogues en code** : `catalogues/additifs.ts` (le nombre de lignes se lit dans le code : `ADDITIFS.length`, voir `additifs.ts` ; E100-E1520) avec, sur CHAQUE ligne, `source: 'connaissance générale — à confirmer par la liste de référence'` — aucun site n'a été lu ni recopié ; le médecin-utilisateur confirme ligne par ligne depuis la console (surcharge). `catalogues/certificateurs.ts` : les dix du cadrage § 8.3, pour le lot 3.
- **Règle d'analyse** (`modules/analyse/analyse-composition-regles.ts`, pure, 40 tests) : codes E du texte (« E 322 », « e322 », « E-322 », « E450ii » → E450, « E 472 e » → E472e : un espace avant la lettre est toléré ; **des chiffres espacés, « E 1 2 0 », ne sont pas lus** — à traiter avec l'OCR, lot 3), tags OFF normalisés, synonymes en mots entiers (gélatine → E441, cochenille/carmin → E120, lécithine → E322, shellac → E904…), ingrédients suspects en toutes lettres. Un code absent de la table vaut « douteux », libellé « non répertorié » (on ne dit jamais « rien à signaler » sur ce qu'on n'a pas examiné). La surcharge de console l'emporte sur le catalogue.
- **Relecture critique du 20/10/2026, décisions du pilote** :
  - un code E écrit entre parenthèses après un libellé l'emporte sur le synonyme : « rouge cochenille A (E124) » → E124 seul (douteux, absent de la table), jamais E120 ; « carmin d'indigo » → rien (E132 si le code est écrit) ; « cochenille » et « carmin » seuls → E120 ;
  - « gélatine de poisson » et « gélatine végétale » → ingrédient suspect douteux « gélatine : origine à examiner », jamais E441 ; « gélatine » seule → E441 non cacher ; **E428** (gélatine, autre numéro) ajouté au catalogue, lu par le tag OFF `en:e428`, le synonyme « gélatine » ne pointant que E441 ;
  - ingrédients suspects : « moules » retiré des fruits de mer (« madeleines cuites dans des moules » → rien ; restent « fruits de mer », « crevette », « crabe », « calamar », « huître », en mots entiers) ; « jambon » sous le libellé « charcuterie » (non cacher) ; **« viande », « bœuf », « veau », « agneau », « poulet », « volaille », « dinde », « fromage » valent douteux sous le libellé « viande ou fromage non certifiés »** (à valider) ; l'avertissement du niveau 4 dit aussi « viande et fromage non certifiés » ;
  - un tag OFF que `normaliserCodeE` ne lit pas (`en:e160a-i`, `en:e14xx`) est gardé tel quel dans `produit.additifs` et COMPTÉ : l'analyse rend `tagsIgnores`, la carte l'écrit en muet (« n additifs non lus ») sous le niveau 4 quand il est > 0 ;
  - notes du catalogue relues : E1105 (l'œuf est parvé ; la question est celle du fromage), E920 douteux (plumes de canard, cheveux humains ; fermentation possible), E901 douteux (cire d'abeille, avec note), E160a douteux (support possible en gélatine, boissons) ; 28 lignes ajoutées (E542 phosphate d'os non cacher, E640 glycine douteux, E153 charbon douteux, E270 et E296 casher « fermentation ou synthèse ; support possible », sels, acides, édulcorants, amidons modifiés, colorants végétaux casher), toutes sous la source provisoire.
- **Synthèse et validité** (`regles/synthese.ts`) : `LigneSynthese.valableJusquAu` (jour ISO) et un argument `aujourdhui` ; une ligne `cite` dont la validité est passée vaut `perime` (jamais « permis »). Le serveur passe le jour du CENTRE (`common/temps/jour-local.ts`, Europe/Paris, testé ; jamais `toISOString().slice(0, 10)`) et convertit la validité en jour local avant la comparaison. **Choix noté : seuil 4 + niveau 2 périmé + composition douteuse → pastille « Non vérifié · additif douteux »** (la composition donne la pastille ; la liste périmée reste lisible sur sa ligne).
- **API, relecture du 20/10/2026** : `GET /produits/:ean` d'un EAN retiré (soft-delete) → 404 `produit_inconnu` sans appel OFF ni upsert (une fiche retirée n'est jamais ressuscitée par une lecture : `setWhere deleted_at IS NULL`) ; une fiche OFF lue il y a plus de 30 jours se relit silencieusement, l'ancienne gardée si OFF échoue ; `POST /produits` avec un EAN connu → 409 `produit_existant` (l'écran recharge alors la fiche) ; `image_front_url` gardée seulement en `https://` sur un hôte `*.openfoodfacts.org`, sinon null ; `derniers()` trié `desc(lu_le)` ; `helmet`, 413 `corps_trop_grand`, 400 `requete_invalide` (voir `console-admin.md`).
- **Carte** (`GET /produits/:ean/carte?seuil=`) : niveaux 1 à 3 « Non vérifié » (ambre, jamais « non ») tant que les lots 2, 3 et 5 n'existent pas ; niveau 4 jamais vert (pastille neutre « Aucun additif repéré · composition seule », ambre « Additif douteux », rouge « Non cacher · composition ») avec l'avertissement du code. La composition s'analyse dès qu'elle est connue (ingrédients OFF ou saisis) et le verdict de niveau 4 ne s'écrit qu'au changement (empreinte dans `detail`).
- **Synthèse partagée** (`regles/synthese.ts`, 10 tests) : lue par l'API et l'écran. Un « oui » ne se lit que jusqu'au seuil et jamais depuis une source périmée ni depuis le niveau 4 ; **un « non cacher » se lit à TOUT niveau, même sous le seuil** (choix le plus protecteur — à valider).
- **Open Food Facts** : `fields=product_name,product_name_fr,brands,image_front_url,ingredients_text_fr,ingredients_text,additives_tags`, User-Agent `Moutar/0.1 (usage familial)`, 8 s. Injoignable → 503 `source_indisponible` (jamais un « aucun ») ; inconnu → 404 `produit_inconnu` ; alors création manuelle (`POST /produits`), l'EAN gardé.
- **Écran** : sobre « en attendant la passe visuelle fun » (direction décidée le 20/10/2026, maquettes `mockups/*-fun.html`) ; **tailles : corps 16 px ; 14 px tolérés pour `.muet` (métadonnées) et les pastilles seulement** (décision du pilote, 20/10/2026, écrite dans `global.css` et `CLAUDE.md`). Les jetons de `mockups/moutar.css` sont les jetons Tailwind (`tailwind.config.cjs`, valeurs `var(--…)`, mode sombre par `prefers-color-scheme` dans `global.css`) ; les classes de la maquette (`.carte`, `.btn`, `.pastille-*`, `.synthese-*`, `.bandeau-*`) vivent dans `@layer components` et sont posées par les composants `Pastille` (le mot obligatoire), `Carte`, `Bandeau`, `Bouton`, `Champ`, `Ecran`. Piège rencontré : Tailwind purge une classe composée dynamiquement (`pastille-${ton}`) → classes en toutes lettres dans les composants + `safelist`.
- Pages à la demande (`React.lazy`, `app/chargement-differe.ts`) : `/scan` charge ZXing seulement s'il n'y a pas de `BarcodeDetector` natif ; la console est un morceau à part. ZXing est un morceau nommé (`manualChunks.zxing`), exclu du précache du service worker (`globIgnores`). Les liens « Photographier le logo » et « Proposer une contribution » sont des textes muets « bientôt (lot 3 / lot 5) », sans apparence de lien.
- Historique (20 derniers) et seuil dans `localStorage` seulement ; aucune donnée de l'utilisateur ne part.
